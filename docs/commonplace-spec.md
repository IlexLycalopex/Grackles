# Commonplace

> **Built, 2026-09-24.** Steps 1 to 8 of the build order below: the schema, the
> content pipeline, the map, every mode, spaced repetition, the daily challenge
> and flashcards. Step 9 (more countries' maps) is still to do. `README.md`
> describes what exists; this document is the argument for why, kept as it was
> written, with the notes at the bottom on where the building departed from it.

A learning app for Grackles. Module one is **Gazetteer**, which teaches the
names of places on a map: US states, countries by continent and capital cities.
Module two is **flashcards**: vocabulary, definitions, or anything else that
works as a prompt and an answer. Both modules share one engine for marking
answers, giving hints, recording progress and scheduling reviews. That engine is
the product. The map and the cards are two ways of showing a question.

The name is a working title. A commonplace book is where people copied down
what they wanted to remember, which describes the app well. Changing the name
means changing one enum value and a table prefix, so it is cheap to change now
and expensive later (see *Open decisions*).

## The rule that shapes everything

> **A card is a fact, not a row in a deck. Decks are selections of facts.**

France appears in *Countries of Europe*, *Countries of the World* and *World
capitals*. If each deck had its own copy of France, learning its shape in one
deck would teach you nothing in another, and the review queue would ask about
France three times. So there is one fact, **the shape of France is called
France**, and every deck that includes France points to it.

Consequences:

- **Knowledge belongs to a person, not a deck or a workspace.** If you learn
  Burkina Faso in *Africa*, it is already learnt when *World* comes up.
- **Directions are separate facts.** Naming a highlighted shape and finding a
  named shape are different skills. People are usually much better at one than
  the other, so each is scheduled separately.
- **A deck is a filter plus a presentation:** which facts it includes, which map
  it draws them on, and which modes suit it.

### Card identity

Cards are identified by a stable text reference, never by a generated id, so
that built-in content can be rebuilt without breaking anyone's history.

| Reference | Fact | Asked as |
|---|---|---|
| `place:FRA:name` | this shape is France | shape → type the name |
| `place:FRA:locate` | France is this shape | name → click the shape |
| `place:FRA:capital` | France's capital is Paris | shape or name → type the capital |
| `capital:FRA:country` | Paris is the capital of France | capital → type or click the country |
| `place:US-TX:name` | this shape is Texas | as above, for states |
| `card:<uuid>:fwd` | custom flashcard, front to back | prompt → answer |
| `card:<uuid>:rev` | custom flashcard, back to front | answer → prompt |

Country keys are ISO 3166-1 alpha-3. Where there is no ISO code (Kosovo:
`XKX`, Northern Cyprus if ever included), the key is the code Natural Earth
uses, and the choice is written down in the build report. State keys are ISO
3166-2 (`US-TX`, `CA-ON`, `GB-...`).

## Where it lives

A new Grackles app, built the same way as the other five.

- **App slug** `commonplace`, **path** `/learn/:workspace`, tables prefixed
  `cp_`. The enum value goes out in a migration on its own, because
  `ALTER TYPE ... ADD VALUE` cannot be used in the transaction that adds it
  (see Blackletter in `README.md`).
- **Workspaces** work as they do everywhere else: members, roles, invites,
  visibility. A workspace is who you play with and who sees your scores. Your
  knowledge travels with you between workspaces (see above).
- **Styling** uses the shared paper tokens in `src/styles/tokens.css`, with its
  own accent colour and a `commonplace.css`, like Cedarhouse.
- **Layout** `CpLayout.astro`, following `BlLayout.astro`.

## Content

### Built-in content is files, not rows

The maps and built-in decks are generated by a script, committed to the repo
and served as static files. They are not stored in the database. The reasons
are the same ones given for the Blackletter word list:

- A list nobody can diff is a list nobody has read. Country names, alternative
  names and disputed territories are exactly the things a reviewer needs to see
  changing.
- Map geometry is large and never changes per user. It belongs on a CDN, not in
  Postgres.
- Stable text references (above) mean a rebuild cannot break anyone's history.

Only what people create or do goes in the database: custom decks, card state,
runs and the daily schedule.

### Map sources

| Map | Source | Licence | Detail |
|---|---|---|---|
| World, continents | Natural Earth Admin 0, countries | Public domain | 1:110m for the world, 1:50m for Europe, the Caribbean and Oceania |
| US states | US Census cartographic boundaries, 1:20m | Public domain | 50 states, DC as an optional extra |
| Capitals | Natural Earth populated places, checked by hand | Public domain | point per capital |
| Next: Canadian provinces, UK counties | Natural Earth Admin 1; ONS boundaries | Public domain; OGL | as above |

Every source is pinned to a version in the build script, not fetched from
"latest".

### The build step

`scripts/build-gazetteer.mjs`, run by hand when the content changes, never at
deploy time.

1. Download the pinned sources.
2. Simplify with mapshaper to a size budget (below).
3. **Pre-project to SVG path strings** with d3-geo. The browser then draws
   plain `<path>` elements and needs no mapping library at all. Projections:
   Equal Earth for the world, a fitted conic for each continent, Albers USA
   (with Alaska and Hawaii as insets) for the states.
4. Work out **neighbours** from the shared borders in the topology
   (`topojson.neighbors`). The Neighbours mode needs them, and so do the
   "same region" wrong options in multiple choice.
5. Work out each shape's **centroid, bounding box and on-screen area** at the
   default zoom, and flag anything under the small-place threshold.
6. Write `src/data/gazetteer/maps/<map>.json` and
   `src/data/gazetteer/decks/<deck>.json`, plus
   `src/data/gazetteer/report.json` (counts, file sizes, every judgement call
   made).

Tools for building (`mapshaper`, `d3-geo`, `topojson-client`) are
devDependencies. None of them ships to the browser.

**Size budget:** 250 KB gzipped for the world map, 120 KB for a continent,
80 KB for US states. The build fails if a map goes over.

### Map file shape

```ts
interface GazetteerMap {
  id: 'world' | 'africa' | 'asia' | 'europe' | 'north-america'
    | 'south-america' | 'oceania' | 'us-states';
  viewBox: [number, number, number, number];
  places: Array<{
    key: string;            // 'FRA', 'US-TX'
    d: string;              // SVG path
    centroid: [number, number];
    bbox: [number, number, number, number];
    small: boolean;         // below the hit-size threshold at default zoom
    neighbours: string[];
    capital?: { name: string; at: [number, number] };
  }>;
  context: string;          // non-playable land drawn in grey (e.g. Canada on the US map)
}
```

### Deck file shape

```ts
interface Deck {
  slug: string;              // 'europe', 'us-states', 'world-capitals'
  title: string;
  map: GazetteerMap['id'];
  facts: Array<'name' | 'locate' | 'capital' | 'capital-country'>;
  modes: ModeId[];           // which modes the deck page offers
  places: Array<{
    key: string;
    answer: string;          // 'Czechia'
    accepts: string[];       // ['Czech Republic']
    capital?: { answer: string; accepts: string[]; also: string[] };
    tags: string[];          // 'disputed', 'territory', 'transcontinental', 'microstate'
  }>;
}
```

### Judgement calls, made once and written down

The build report lists every one of these, so they can be reviewed as a diff.

- **Disputed places** (Kosovo, Taiwan, Western Sahara, Palestine) are
  included, tagged `disputed`, and labelled with their common English name and
  no claim of status. There is a deck setting to leave them out. Natural Earth's
  de facto borders are used.
- **Territories** (Greenland, French Guiana, Puerto Rico, the Falklands, New
  Caledonia) are drawn, tagged `territory`, and off by default. Where they are
  off they are drawn in the grey context layer, so the map does not show a
  hole.
- **Transcontinental countries** (Russia, Turkey, Kazakhstan, Georgia,
  Armenia, Azerbaijan, Cyprus, Egypt) belong to every continent deck they
  touch. Because a card is a fact, this costs nothing.
- **Countries with more than one capital** (South Africa, Bolivia, Malaysia,
  the Netherlands, Eswatini, Sri Lanka, Côte d'Ivoire, Benin) accept any
  official capital. The reveal shows all of them, with one line saying which
  does what.
- **Alternative names:** Czechia or Czech Republic, Myanmar or Burma, Côte
  d'Ivoire or Ivory Coast, Eswatini or Swaziland, Türkiye or Turkey, Timor-Leste
  or East Timor, Cabo Verde or Cape Verde, North Macedonia or Macedonia,
  the DRC and the Republic of the Congo under all their usual forms. The
  canonical answer is the name in current UK Foreign Office use.

## Marking an answer

One function, `mark(input, card, deck)`, in `src/lib/commonplace/mark.ts`,
shared by every mode and fully unit-tested. It returns one of four results.

| Result | Meaning | Shown as | Counts as known |
|---|---|---|---|
| `clean` | right first time, no hints | green, tick | yes |
| `close` | accepted with a typo | amber, correct spelling shown | partly |
| `hinted` | right after at least one hint | blue, hint icon | no |
| `revealed` | gave up or ran out of attempts | red, name shown | no |

Colour is never the only signal. Each result also has an icon and a fill
pattern, for colour blindness and for printouts.

### Normalising

Both the input and every accepted answer are passed through the same steps
before they are compared:

1. Unicode NFKD, then remove combining marks (`Côte` becomes `cote`).
2. Lower case.
3. `&` becomes `and`; `st` and `st.` at the start of a word become `saint`.
4. Remove all punctuation, and treat hyphens and runs of spaces as a single
   space.
5. Remove a leading `the`.

### Accepting typos

After normalising, an exact match against the answer or any accepted name is
`clean`. If there is no exact match, the Damerau-Levenshtein distance decides:

| Answer length | Typos allowed |
|---|---|
| 1 to 4 letters | 0 |
| 5 to 8 | 1 |
| 9 or more | 2 |

**A typo is never accepted if it lands on another real answer in the same
deck.** Niger and Nigeria, Guinea and Guinea-Bissau, Dominica and Dominican
Republic, Austria and Australia, Iran and Iraq, Mali and Malawi, Slovakia and
Slovenia. Typing one of these when the answer is the other is a wrong answer,
not a close one. The build checks every deck for such pairs and records them in
the report, and the marking test suite asserts every pair.

Flashcard decks can make marking stricter:

- **Accents:** ignored (default for maps), or a missing accent marks the answer
  `close` (default for language decks).
- **Typos:** allowed or not.
- **Case:** ignored everywhere, except in decks set to case-sensitive (for
  German nouns, for example).

### Wrong answers

A wrong answer shakes the input and keeps the place selected. Three wrong
attempts on a card reveals it (this can be changed per run: 1, 3, 5 or
unlimited). Every wrong attempt is recorded, because "got it on the third try"
is useful to know.

## Hints

A ladder. Each press goes one step further, and the last step is a reveal.

**For a typed answer:**

1. First letter: `B…`
2. Letter count, keeping spaces and hyphens: `B _ _ _ _ _ _   _ _ _ _`
3. One more letter per press, left to right: `B u _ _ _ _ _   _ _ _ _`
4. Reveal.

**For a click answer (Find it):**

1. Show the continent or region on the map.
2. Narrow it to one quarter of that region.
3. Pulse the neighbours of the target.
4. Reveal: the shape flashes.

**For capitals,** there is an extra first step: show the capital's dot.

A card marked `hinted` also records how many hints were used. One hint and five
hints are different amounts of knowing. The ladder can be turned off as a run
setting.

## Ways to play

Each run is a **mode** (what you are asked), with **settings** (the rules
around it), over a **scope** (which places are included).

### Modes

| Mode | What happens | Best for | Updates reviews |
|---|---|---|---|
| **Name it** | Click a shape, type its name | Main learning mode | yes |
| **Find it** | You are given a name, click the shape | The other direction | yes |
| **Free recall** | One text box. Type any name in any order and it fills in on the map. No Enter needed | Testing yourself, the Sporcle style | no, see below |
| **Capitals** | Shape highlighted, type its capital. Can be reversed: given a capital, type or click its country | Capitals decks | yes |
| **Outline** | One shape on its own, with no map around it, scaled to fill the screen | Hard mode, and for decks where shape is the point | yes |
| **Neighbours** | A country is highlighted; name everything that borders it | Understanding a region, not just labels | no |
| **Multiple choice** | Four options, wrong options drawn from the same region | New decks, and one-handed use on a phone | no |
| **Learn** | New places introduced three at a time: shown and named, then asked, then mixed in with earlier ones | Starting a deck from nothing | yes |
| **Review** | Whatever is due today, across all decks, each in its own mode | Daily habit | yes |
| **Daily challenge** | Ten places, the same for everyone in the workspace, one attempt a day, with a scoreboard | Playing with other people | yes |
| **Flashcards** | Prompt, then type the answer, or flip the card and rate yourself | Module two | yes |

**Why Free recall, Neighbours and Multiple choice do not update reviews.** A
review score should mean "I can recall this one fact when asked". Free recall
lets you type names you know in whatever order suits you, which avoids the ones
you don't. Multiple choice tests recognition, not recall. Neighbours tests
knowing the region. All three still record runs, results and personal bests.

In Free recall, a match must be exact after normalising. Typo tolerance would
fill in the wrong countries as you type (`nige` is on its way to both Niger and
Nigeria).

### Settings

| Setting | Options | Default |
|---|---|---|
| Timer | off, count up, countdown 3, 5, 10 or 15 minutes | count up |
| Sudden death | first wrong answer ends the run | off |
| Attempts before reveal | 1, 3, 5, unlimited | 3 |
| Hints | on, off | on |
| Order | random, west to east, largest first, smallest first | random |
| Round length | whole map, 10, 20, 50 | whole map |
| Labels on answered places | on, off | on |
| Auto-advance | stay, next random, nearest unanswered | nearest unanswered |
| Include territories / disputed | per deck | territories off, disputed on |

A **personal best** is kept for each combination of deck, mode, scope and the
settings that change difficulty (timer, sudden death, hints, round length).
Beating your time without hints is not the same achievement as beating it with
them.

### Scope

A run can cover a whole deck or part of one: a sub-region (Scandinavia, the
Balkans, the Caribbean, New England), only places you have not learnt yet, only
places you have got wrong recently, or only small places. Sub-regions are tags
in the deck file.

## The map on screen

- **Inline SVG**, one `<path>` per place with `data-key`, styled by result
  class. No canvas and no mapping library, so it is sharp at any zoom, and every
  shape is a real element for keyboard and screen reader use.
- **Zoom and pan:** mouse wheel, trackpad, pinch, drag. Double-click zooms to a
  shape. A button returns to the full map. This works by changing the viewBox,
  which keeps line widths constant.
- **Small places:** anything flagged `small` also gets a circle hit target,
  at least 24 px on desktop and 44 px on touch screens. There is also a **small
  places tray** beside the map: a list of chips you can pick from instead of
  clicking the map. Malta, Luxembourg, Rhode Island, Delaware and most of the
  Caribbean are playable on a phone without zooming.
- **Context:** land that is not part of the game is drawn in grey, so the
  shapes stay recognisable. Mexico and Canada appear around the US, for example.
- **Hover** outlines a shape, but never names it before it is answered.

### On a phone

- The input docks above the on-screen keyboard and the map shrinks to fit the
  space left.
- A selected shape stays in view when the keyboard opens.
- Multiple choice and the small places tray are one tap away.
- The layout works at 320 px wide and never scrolls sideways.

### Keyboard

| Key | Action |
|---|---|
| Enter | submit |
| `?` or Ctrl+H | next hint |
| Tab / Shift+Tab | next / previous unanswered place |
| Esc | deselect; press again to leave the run (after confirming) |
| `+` / `-` / `0` | zoom in / out / fit |
| Ctrl+Enter | give up on this place (reveal) |

A **list view** shows the same run as an ordered list, for screen readers and
for people who prefer it. The same run and the same marking, without the map.

## Screens

1. **Hub, `/learn/:workspace`.** Today's review count, the daily challenge,
   recently played decks, and a line such as "12 due, about 4 minutes".
2. **Deck page, `/learn/:workspace/deck/:slug`.** The deck's map, **coloured by
   how well you know each place** (see Progress), the mode picker, settings,
   your personal bests, and scope options.
3. **Play, `/learn/:workspace/play/:slug?mode=&...`.** The map or card, the
   input, hint button, progress bar (`37 / 54`), timer, and a give-up button.
4. **Results.** The map coloured by result, time, accuracy, clean / close /
   hinted / revealed counts, the difference from your personal best, and
   "play only the ones I missed".
5. **Review, `/learn/:workspace/review`.** A queue of due cards, each shown in
   the right mode with the map zoomed to its region.
6. **Progress, `/learn/:workspace/progress`.** Per-deck mastery and a history.
7. **Daily, `/learn/:workspace/daily`.** Today's ten, then the scoreboard.
8. **Deck editor, `/learn/:workspace/decks/new` and `.../edit`.** Module two.

## Remembering: spaced repetition

This is the feature that turns a game into a way of learning. Each fact has a
schedule per person. Getting it right pushes the next review further away, and
getting it wrong brings it back soon.

**Algorithm: FSRS**, using the `ts-fsrs` package (MIT). It is the current open
standard, it needs fewer reviews than SM-2 for the same retention, and it takes
four grades, which match the four marking results exactly:

| Result | FSRS rating |
|---|---|
| `clean`, answered quickly (under 5 s for a map, under 8 s for a flashcard) | Easy |
| `clean` | Good |
| `close`, or `clean` after a wrong attempt, or `hinted` with one hint | Hard |
| `hinted` with two or more hints, or `revealed` | Again |

- **Target retention** 90 per cent, can be changed on the Progress page.
- **New cards per day:** 20 by default. Learn mode introduces them; Review
  never piles them on unannounced.
- **Any mode that updates reviews counts.** Playing the Europe deck in Name it
  mode updates the schedule for those facts, so casual play and deliberate
  review feed one record.
- **The scheduling runs in the browser.** Only the resulting state is saved.
  `ts-fsrs` is small and deterministic, so the server has no reason to
  recalculate it.

### Progress on a map

The deck page and the Progress page colour every place by how well you know it:
not seen, learning, due, known, and mastered (predicted recall above 95 per cent
for more than 30 days ahead). It is the map you are learning, showing what you
know, which makes gaps obvious. For example: "the whole of central Africa is
still grey".

## Data model

Only what people make or do. Maps and built-in decks are files (above).

```sql
-- Custom decks (module two, and later custom map selections)
create table cp_decks (
  id            uuid primary key default gen_random_uuid(),
  workspace_id  uuid not null references workspaces(id) on delete cascade,
  slug          text not null,
  title         text not null,
  kind          text not null check (kind in ('flashcards', 'map-selection')),
  settings      jsonb not null default '{}',   -- strictness, directions, map id
  created_by    uuid not null references profiles(id),
  created_at    timestamptz not null default now(),
  updated_at    timestamptz not null default now(),
  unique (workspace_id, slug)
);

create table cp_cards (
  id        uuid primary key default gen_random_uuid(),
  deck_id   uuid not null references cp_decks(id) on delete cascade,
  position  int  not null,
  prompt    text not null,
  answer    text not null,
  accepts   text[] not null default '{}',
  hint      text,
  notes     text,                                -- shown after answering
  tags      text[] not null default '{}',
  reverse   boolean not null default false,      -- also ask back to front
  place_key text                                 -- for map-selection decks
);

-- One row per person per fact per direction. Never per workspace.
create table cp_card_state (
  user_id      uuid not null references profiles(id) on delete cascade,
  card_ref     text not null,                    -- 'place:FRA:name', 'card:<uuid>:fwd'
  stability    real not null,
  difficulty   real not null,

  last_at      timestamptz not null,

);
create index on cp_card_state (user_id, due_at);

-- The daily challenge schedule, written once on first request, like bl_puzzles
create table cp_daily (
  id            uuid primary key default gen_random_uuid(),
  workspace_id  uuid not null references workspaces(id) on delete cascade,

  deck_ref      text not null,

);

-- One row per game played

  deck_ref      text not null,                   -- built-in slug or 'deck:<uuid>'
  mode          text not null,
  settings      jsonb not null,
  scope         jsonb not null,
  pb_key        text not null,                   -- deck + mode + scope + difficulty settings
  started_at    timestamptz not null default now(),   -- server clock
  finished_at   timestamptz,                          -- server clock
  total         int not null,
  clean         int not null default 0,
  close         int not null default 0,
  hinted        int not null default 0,
  revealed      int not null default 0,
  daily_id      uuid references cp_daily(id)
);

-- One row per card answered in a run
create table cp_run_answers (
  run_id      uuid not null references cp_runs(id) on delete cascade,
  card_ref    text not null,
  result      text not null,
  attempts    smallint not null,
  hints       smallint not null,
  ms          int not null,
  answered_at timestamptz not null default now(),

);

```

### Who can read what

- **Decks and cards:** readable by workspace members, writable by editors and
  owners. The same `app.can_read()` / `app.can_write()` checks every other app
  uses.
- **Card state:** only your own rows. No one else in the workspace can see what
  you have forgotten. There is no workspace column to check, because knowledge
  belongs to the person.
- **Runs and answers:** your own rows in full. Other members see **scores only**
  (counts, time, result per card), through a `SECURITY DEFINER` function, the
  same approach as the Blackletter scoreboard. For the daily challenge this
  stops the scoreboard from giving the answers away.

### How writes happen

Functions, not inserts, where the rules matter. The same split as Blackletter.

- `cp_start_run(workspace, deck_ref, mode, settings, scope)` returns a run id
  and stamps `started_at` on the server.
- `cp_record_answer(run_id, card_ref, result, attempts, hints, ms, state)`
  writes the answer and the new card state together. Called after each answer,
  so closing the tab halfway through loses nothing.
- `cp_finish_run(run_id)` stamps `finished_at` on the server and returns the
  personal best comparison. **Times come from the server clock,** so a
  personal best cannot be set by editing a request.
- `cp_daily_today(workspace)` creates today's ten on first request and returns
  them; `cp_daily_scores(workspace, day)` returns the scoreboard. One daily run
  per person per day is enforced in `cp_start_run`.

### A trade-off, stated plainly

**Answers are marked in the browser**, because marking has to feel instant. The
catch is that someone who edits their requests could post a false result. Among
friends and family this is acceptable, and it is a different situation from
Blackletter, where the answer itself is the secret. On a map the question is
the shape, and the shape is in the page.

If the daily scoreboard ever matters enough to protect, the matcher can move
into SQL (`unaccent` and `fuzzystrmatch` are both available in Supabase), with
the daily answers held server-side as Blackletter's are. The marking tests are
written against inputs and outputs, not the TypeScript, so they can be run
against both versions.

## Module two: flashcards

Uses the same engine. What it adds:

- **The deck editor.** A table of cards you can type straight into: prompt,
  answer, accepted alternatives, hint, notes, tags, and a "reverse" tick box.
- **CSV import.** Columns: `prompt, answer, accepts, hint, notes, tags,
  reverse`, with `accepts` and `tags` separated by `|`. The import shows a
  preview with problems marked (duplicates, empty answers, two cards whose
  answers collide after normalising) before anything is saved. Also exports to
  the same format.
- **Two ways to answer:**
  - **Typed:** marked exactly as map answers are, with the deck's strictness
    settings.
  - **Self-graded:** flip the card, then press Again, Hard, Good or Easy. Best
    for definitions and anything else too long to type exactly.
- **Both directions** for language decks: English to French and French to
  English are separate facts with separate schedules.
- **Accent keys:** for language decks, a row of the accented letters the deck
  actually uses, shown above the input.
- **Later:** pronunciation through the browser's built-in speech synthesis (no
  service, no cost), images on cards, and cloze deletion (`The capital of
  {{Peru}} is Lima`).
- **Map-selection decks** reuse the editor to save a custom set of places, such
  as "the countries I keep confusing", or "everywhere I've been".

## Testing

Following the repo's existing `node --test` setup (`npm test`).

- **Marking** (`mark.test.ts`): normalising, the typo thresholds, every
  near-collision pair above, multiple capitals, accent and case strictness.
  Each deck's collision report is turned into test cases automatically.
- **Deck integrity** (`gazetteer-decks.test.ts`): every deck key exists in its
  map; no two answers in one deck collide after normalising; every capital has
  a location; every tag used for scope exists.
- **Map budget:** file sizes within budget; every place with an area under the
  threshold is flagged `small`.
- **Scheduling:** the result to FSRS rating mapping, and that Free recall,
  Neighbours and Multiple choice never write card state.
- **Database** (`supabase/tests/`): card state is only readable by its owner;
  the scoreboard function returns no answers; one daily run per person per day;
  times are the server's.
- **In the browser:** one Playwright run per mode at 320 px and at desktop
  width, including a small place picked from the tray.

## Build order

The whole spec is in scope. This is only the order, chosen so that each step is
usable and tested before the next one relies on it.

| Step | Delivers | Done when |
|---|---|---|
| 1. Foundation | Enum migration, tables, RLS, functions, app registry entry, workspace, layout | Database tests pass; `/learn/:workspace` loads for a member and refuses a non-member |
| 2. Content pipeline | Build script, all launch maps and decks, report | Budgets met; integrity tests pass; report reviewed by Jamie |
| 3. Map and marking | Map component, zoom, small places tray, `mark()`, hint ladder | Marking tests pass; Malta can be answered on a 320 px screen without zooming |
| 4. Core modes | Name it, Find it, Capitals, results screen, personal bests | A full US states run can be finished, reloaded halfway without loss, and beaten |
| 5. Learning | FSRS, Review, Learn mode, progress map | A place missed today is due again tomorrow; the progress map matches card state |
| 6. More ways to play | Free recall, Outline, Neighbours, Multiple choice, all settings, scope | Every mode has a passing Playwright run |
| 7. Together | Daily challenge and scoreboard | Two members get the same ten; neither can see the other's answers |
| 8. Flashcards | Editor, CSV import and export, typed and self-graded, both directions | A 200-row CSV imports with problems shown before saving |
| 9. Next wave content | Canadian provinces, UK counties, Australian states, flags | Same integrity tests as launch content |

## Not covered

- Accounts outside Grackles. Anyone playing needs a Grackles sign-in and access
  to the workspace.
- Working offline. The maps are static files, so a service worker could cache
  them later. Card state would need a queue for answers recorded offline, which
  is a larger piece of work.
- Public leaderboards across workspaces.
- AI-generated decks. The AI governance in `docs/ai-architecture.md` would make
  this straightforward later ("make me a deck of 50 common Spanish verbs"),
  but it is not in this spec.

## Open decisions

Defaults are in place for all of these, so none of them blocks the build.

| Decision | Default | Why it is worth a second look |
|---|---|---|
| Name and path | Commonplace at `/learn` | Renaming is cheap until the enum exists |
| Scheduling algorithm | FSRS via `ts-fsrs` | SM-2 is simpler to explain but needs more reviews |
| Where answers are marked | In the browser, times on the server | Only matters if the daily scoreboard becomes competitive |
| Disputed places | Included, labelled neutrally, can be turned off | A content decision rather than a technical one |
| Canonical names | UK Foreign Office usage | Affects which name is shown as the answer, not which are accepted |
| New cards per day | 20 | Too many makes review a chore; too few makes a 197-country deck take months |

## What the building changed

- **Custom decks live at `/cards/:deck`, built-in ones at `/deck/:deck`.** Two
  paths rather than one with a check constraint keeping slugs apart, so a deck
  called "Europe capitals" can exist without shadowing the built-in one.
- **The small places tray is numbered, not named, in Name it.** A chip saying
  "Malta" is the answer. Chips show a number until answered, then the name. In
  Find it there is no tray: the enlarged dots are the targets.
- **Somaliland is drawn inside Somalia and Northern Cyprus inside Cyprus.** The
  atlas draws them apart; no UN member recognises either, and a quiz asking for
  them by name takes a side.
- **Tuvalu is a dot.** The 1:50m atlas does not draw it at all.
- **The list view for screen readers is not built.** What exists instead: every
  question is announced in a live region with its region, Tab moves between
  unanswered places in Name it, and all controls are real buttons. A full list
  view is the first accessibility item still open.
- **Saved map selections (the spec's `map-selection` decks) are not built.** The
  `kind` column is there for them.
